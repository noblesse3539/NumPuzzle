# [0002 | 2026-09-08] 추가 01회차 — 이어지는 NEXT 선택

상태: 구현 완료 · 실행 검증 전

## 문제와 판단

제안서 4·10쪽의 흐름을 방해한 주요 요인은 화면에 없는 숫자를 NEXT로 선택하는 경우였습니다. 이미 보여준 두 숫자는 유지하면서, 새 preview를 고르는 시점에만 개선합니다.

## 구현한 내용

- `generateNextPreview()`에 화면상의 모든 현재 정답 선택 이후에도 실제로 남아 있는 숫자 후보를 계산했습니다.
- 초반 안전 보정 스테이지와 버스트 중에 적용합니다. 기존 후보에 적합한 숫자가 있으면 우선 유지하고, 없을 때만 안전한 후보군으로 바꿉니다.
- 가능한 후보가 없으면 기존 생성 규칙과 강제 대기 시간 보호로 돌아갑니다. 현재 NEXT나 게시된 preview를 바꿔치기하지 않습니다.

## 정적 검토 기록

`simulateFrontierAfterChoice()` 결과의 `sourceType`까지 확인하도록 코드를 검토했습니다. 미래 웨이브에 같은 숫자가 있다는 이유만으로 즉시 선택 가능하다고 처리하지 않습니다. 고스테이지의 버스트 외 선택 규칙은 유지됩니다.

창작자님 요청에 따라 실제 플레이, 브라우저/자동화 테스트, 빌드 실행과 배포는 수행하지 않았습니다. 이 기록은 동작 성공이나 몰입도 향상을 검증했다는 의미가 아닙니다.

## 통합 정리

통합 정적 검토에서 즉시 후보의 숫자뿐 아니라 출처도 화면상의 블록으로 유지하도록 보완했습니다.

## 남은 과제

실제 판에서 대기 빈도가 줄었는지와 다중 정답 선택 후의 경로를 확인해야 합니다. 모든 상황에서 대기 제거를 보장하는 구현은 아닙니다.
