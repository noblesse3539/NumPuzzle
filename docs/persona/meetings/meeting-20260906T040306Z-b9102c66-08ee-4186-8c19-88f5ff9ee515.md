# FOURCAST 개발 전용 테스트 벤치 도입

## 결론\nFOURCAST의 테스트 기능은 실제 게임 안의 숨은 메뉴가 아니라 개발용 웹 테스트 벤치로 분리한다.\n\n## 범위\n넓은 데스크톱 화면에서 실제 모바일 게임 프레임과 바깥 조작 패널을 함께 제공한다. 조작 패널은 스테이지 선택, 시작·초기화, 일시정지·재개, 상태 관찰, 이름 있는 시나리오 실행만 제공한다. 첫 시나리오는 Stage 11 전환의 두 번째 Next 맥동, 두 Next 연결 적중 잔광, 레드라인 자동 초기화다. 임의 함수 실행 콘솔과 임의 상태 편집은 제공하지 않는다.\n\n## 재현 원칙\n시나리오는 보드·큐·난수·시간 같은 사전조건만 준비한다. 이후에는 실제 라인 입력, 적중 판정, 스테이지 전환, 레드라인 이벤트를 통해 연출이 발생해야 한다. 따라서 실험실은 가짜 연출 재생기가 아니라 실제 플레이 경로의 검증 도구가 된다.\n\n## 배포 보호\n프로덕션과 Lab은 별도 진입점과 산출물로 만들고, 실제 배포는 프로덕션 산출물만 허용한다. Lab 파일, 시나리오 식별자, 디버그 전용 API가 프로덕션 산출물에 남으면 빌드 검증이 실패해야 한다. 단순 URL 플래그나 숨긴 패널은 사용하지 않는다.\n\n## 보호 범위\n모바일 플레이 화면, 게임오버 결과 화면, Classic은 이번 작업에서 변경하지 않는다.
