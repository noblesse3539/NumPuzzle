# FOURCAST 몰입도 개선: 구현 결과와 다음 과제

작성일: 2026-09-08

후속 작업: [추가 10회 개선 총괄](추가_10회_개선_총괄.md) 및 [통합 검증과 20스테이지 직접 플레이](통합_검증과_20스테이지_플레이.md). 아래 내용은 최초 작업 시점의 기록이며 최신 검증 결과는 후속 문서를 참고하세요.

## 이번 작업의 판단

FOURCAST의 강점은 **현재 숫자를 맞히면서 다음 숫자를 읽는 짧은 판단의 연속**입니다. 이 리듬 위에 ‘힘을 모았다가, 내가 선택한 순간에 위기를 뒤집는 장면’을 추가했습니다.

기준 문서는 `docs/FOURCAST 기능 제안.pdf`입니다. 문서의 6쪽과 12쪽에서 대표 기능으로 추천한 **수동 4연쇄 버스트**를 중심으로 선택했습니다. 3쪽의 정답 손맛, 8쪽의 클러치, 9쪽의 최고기록을 함께 연결했습니다. 문서가 대안으로 제시한 자동 피버는 동시에 넣지 않았습니다.

이번 작업은 게임 구현과 로컬 검증까지입니다. 서비스 배포는 수행하지 않았습니다.

## 플레이어가 만나는 변화

### 1. 직접 여는 4연쇄 버스트

정답을 모으면 네 라인 버튼 바로 아래의 버스트 게이지가 채워집니다. 준비된 힘은 즉시 쓰거나 다음 위기까지 가지고 갈 수 있습니다.

| 항목 | 현재 규칙 |
| --- | --- |
| 충전 | 정답 블록 16개 제거 |
| 발동 | 충전 완료 후 BURST 버튼 누르기 |
| 낙하 | 평소 속도의 40% |
| 제한 시간 | 선택 가능한 플레이 시간 6초 |
| 성공 | 제한 시간 안에 4연속 정답 제거 |
| 보상 | 네 번째 정답에 추가 100점 |
| 오답 | 발동 중이면 즉시 종료, 충전 중이면 4칸 차감 |
| 시간 초과 | 버스트 종료, 추가 벌점 없음 |
| 다시 충전 | 종료 후부터 새 정답으로 충전 |

버스트 중에는 청록색 보드 테두리와 어두운 버튼 배경으로 상태를 구분합니다. 버튼에는 `0 / 4`부터 시작하는 연쇄 횟수와 남은 시간이 표시됩니다. 성공 시 `4 CHAIN! +100`을 보여줍니다.

**공정성을 위한 처리:** NEXT가 아직 나타나지 않은 블록을 가리킬 때는 정답을 누를 방법이 없습니다. 이때 버스트 제한 시간은 멈추고 ‘다음 블록 대기’를 표시합니다. 보드와 웨이브는 느린 속도로 계속 진행합니다. 따라서 실제 경과 시간은 6초보다 길 수 있습니다. 숨겨진 숫자를 정답으로 바꾸거나 블록을 자동 제거하지 않습니다.

스테이지 전환에는 충전량과 진행 중인 연쇄를 유지합니다. 일시정지·카운트다운·스테이지 사이 휴식에서는 버스트 시간이 소모되지 않습니다. 재시작에는 모두 초기화합니다. 날아가는 입력이나 대기 입력이 있을 때는 발동할 수 없어 발동 전 입력이 버스트 정답으로 섞이지 않습니다.

버스트는 무적이 아닙니다. 슬로모션 중에도 블록이 레드라인 판정 위치에 도달하면 게임이 끝납니다. 낙하와 웨이브 간격, 스테이지 제한 시간에 같은 속도 배율을 적용해 블록 공급과 스테이지 시간이 서로 어긋나지 않도록 했습니다. 발사체와 정답 처리 속도는 그대로 유지했습니다.

### 2. 맞힌 자리에 점수가 남는 손맛

정답 블록을 제거한 자리에 실제 획득 점수와 작은 파편이 나타납니다. 기존 콤보 점수, 완벽 보너스, 버스트 보너스를 합산한 값을 보여줍니다. 효과는 터치 입력을 가로채지 않으며 짧은 시간 뒤 정리됩니다.

이번 구현은 시각적 보상에 집중했습니다. 점수 HUD까지 날아가는 조각, 새로운 효과음과 진동은 후속 범위입니다. 운영체제의 모션 감소 설정에서는 파편과 점수 이동을 끕니다.

### 3. 실제로 살아났을 때만 ‘살았다!’

정답이 맞는 순간 블록이 실패 판정 위치에서 블록 높이의 35% 이내에 있었고, 제거를 마친 뒤 다른 라인에도 그 정도로 위험한 블록이 없으면 ‘살았다!’를 보여줍니다.

위험한 블록 하나를 제거해도 다른 라인에 즉각적인 위협이 남아 있으면 축하하지 않습니다. 생존 보너스나 자동 구조 기능은 없고, 플레이어가 실제로 만든 위기 탈출을 알아봐 주는 피드백입니다.

### 4. 이번 판의 목표가 되는 최고기록

한 판 시작 시 종전 최고기록을 기억합니다. 새 기록까지 100점 이내로 가까워지면 남은 점수를 표시하고, 실제로 넘으면 최고기록 돌파를 알립니다. 동점은 갱신으로 처리하지 않습니다.

기록이 없는 첫 판에는 임의의 목표를 만들지 않습니다. 기존 게임오버 성취 화면과 로컬 최고점 저장 흐름을 유지했습니다. 한 판 중 표시한 새 기록은 기존 규칙에 따라 게임오버 시 저장되므로, 게임 도중 탭을 닫으면 저장되지 않습니다.

## 검증과 구현 구조

주요 변경 파일은 다음과 같습니다.

| 파일 | 역할 |
| --- | --- |
| `app.js` | 버스트 상태·점수·시간, 클러치 판정, 최고기록 추격, 시각 효과, 한국어·영어 안내 |
| `index.html` | 짧은 상황 알림과 하단 버스트 버튼 |
| `styles.css` | 충전·발동 상태, 정답 효과, 작은 화면 및 모션 감소 대응 |
| `scripts/test-immersion.cjs` | 실제 브라우저 통합 테스트 |

새로운 상태는 `state.immersion`에 모았습니다. 기존 `window.FOURCAST.getState()`에서 충전량, 남은 시간, 연쇄, 성공 횟수와 클러치 횟수를 관찰할 수 있습니다. `activateBurst()`는 실제 버튼과 같은 진입 조건을 사용하는 공개 조작 함수입니다. 테스트 전용 상태 준비 코드는 테스트 중 브라우저 응답에만 주입되며 배포 파일에는 들어가지 않습니다.

검증 범위:

- 기존 콤보 점수 유지와 4연쇄 100점의 단일 지급
- 충전 완료, 중복 발동 방지, 오답 종료, 시간 초과, 재시작 초기화
- 낙하·스테이지 시간의 40% 배율, 강제 블록 대기 중 시간 보존
- 스테이지 전환 중 연쇄 유지, 일시정지 상태에서 조작 차단
- 다른 위험이 남은 경우를 포함한 클러치 판정
- 최고기록 초과 판정과 첫 판 처리
- 버스트 중에도 정상적으로 작동하는 레드라인 게임오버
- 320×568, 390×844, 430×932, 1280×900 화면의 버튼 위치·보드 높이·가로 넘침
- 영어 안내, 모션 감소 설정, 브라우저 실행 오류
- 수정하지 않은 배포용 게임의 시작·카운트다운·실제 라인 버튼·버스트 버튼 조작
- 프로덕션/Lab 분리 빌드 및 배포 허용 파일 검사

실행 방법:

```sh
npm run build
npm run verify:build
node scripts/test-immersion.cjs
```

브라우저 테스트에는 Node.js에서 접근 가능한 `playwright` 패키지와 설치된 Google Chrome이 필요합니다. 게임 실행과 빌드는 여전히 추가 패키지가 필요 없습니다. Codex의 번들 패키지를 사용한다면 해당 패키지 경로를 `NODE_PATH`로 지정해 실행할 수 있습니다. 테스트 화면은 `tmp/immersion`에 생성됩니다.

## 앞으로의 방향: 기능의 수보다 기억에 남는 한 판

**추천 방향은 수동 버스트를 FOURCAST의 대표 장면으로 다듬는 것입니다.** 먼저 플레이어가 준비 상태를 알아보고, 자신이 고른 타이밍에 사용하며, 성공했을 때 다시 해보고 싶어지는지를 확인해야 합니다. 이번 상수들은 출시 최적값이 아니라 검증할 첫 기준입니다.

### 우선순위 1: 실제 휴대폰에서 버스트의 재미와 공정성 확인

- 초보자와 숙련자가 설명 없이 준비 버튼을 발견하는지 확인합니다.
- 발동 시점, 네 번의 성공률, 오답·시간 초과 비율, 미사용 채 사망하는 비율을 봅니다.
- NEXT 공급 대기가 얼마나 자주·오래 발생하는지 확인합니다. 대기 때문에 절정이 끊긴다면 이후에는 버스트용 공급 보장 설계를 검토합니다.
- 16개 충전·6초·40%·100점은 한 번에 하나씩 바꿔 비교합니다.
- 작은 휴대폰에서 추가 버튼이 기존 네 라인 조작과 숫자 읽기를 불편하게 만들지 확인합니다.

초기에는 짧은 관찰 플레이와 기록표면 충분합니다. 이번 작업에 외부 분석 수집은 추가하지 않았습니다. 실제 재도전율과 몰입도가 좋아졌다는 성과는 아직 측정하지 않았습니다.

### 우선순위 2: 소리와 손끝까지 보상 연결

기존 BGM은 단일 음원입니다. 제안서의 ‘잘할수록 베이스·드럼·멜로디가 추가되는 음악’을 구현하려면 분리된 음원과 박자 기준이 필요합니다. 먼저 짧은 정답 효과음과 버스트 시작·완성 사운드를 설계하고, 효과음·진동을 각각 끌 수 있게 만드는 것을 권합니다. iOS Safari와 Android 실기기의 음성 재생 정책, 이어폰·무음·복귀 상황도 검증해야 합니다.

### 우선순위 3: 번개 연쇄와 패턴·완급

빠른 정답 위치를 연결하는 번개는 버스트 성공 장면을 보강할 수 있습니다. 다만 NEXT와 위험선보다 시선을 더 빼앗지 않아야 합니다. 반복·교차·순환 패턴과 해소 구간은 숫자 생성 규칙, 막힘 방지, 고스테이지 난도에 영향을 주므로 별도 실험으로 다루는 것이 좋습니다.

### 우선순위 4: 출시 운영 기준 정리

버스트 보너스 도입으로 이전 버전보다 높은 점수가 나올 수 있습니다. 현재는 개인 최고기록을 보존하지만, 향후 경쟁 순위표를 도입한다면 규칙 버전별 기록 분리가 필요합니다. 저장 중단 대응, 장시간 플레이의 효과 비용, 기존 Lab 시나리오 전체 회귀, iOS·Android 실제 터치 검증도 출시 전 과제입니다.

## 완료 범위와 남은 한계

수동 버스트, 정답 위치의 시각 보상, 실제 위기 탈출 피드백, 개인 최고기록 추격을 구현했습니다. 자동 피버, 다층 음악, 진동, 번개 궤적, 새 패턴 생성, 온라인 순위표는 후속 과제입니다. 데스크톱 Chrome의 모바일 화면 검증은 실물 휴대폰 검증을 대체하지 않습니다.
