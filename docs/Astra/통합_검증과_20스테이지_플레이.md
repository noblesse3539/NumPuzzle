# FOURCAST 통합 테스트·수정·20스테이지 직접 플레이 기록

작성일: 2026-09-08

후속 작업: [5회 구현·통합 검증·새 20스테이지 플레이 기록](후속_5회_개선_총괄.md). 아래 내용은 이전 빌드에 대한 이력입니다.

## 완료 결과

추가 10회 개선을 실제로 검증하고 발견한 문제를 수정했습니다. 브라우저의 실제 버튼을 눌러 **20스테이지 목표 48개를 모두 제거하고, 9,043점으로 21스테이지에 진입**했습니다. 마지막 콤보는 92이며 로컬 게임을 일시정지해 남겼습니다. 배포는 하지 않았습니다.

첫 장기 플레이는 16스테이지에서 17,099점·440콤보로 끝났습니다. 이 실패에서 대기 안내의 문제를 발견해 고친 뒤 다시 플레이했습니다. 조작 연결을 바꾸는 동안 입력하지 못해 1스테이지·0점으로 종료된 준비용 시도도 있었으며, 두 판의 성과 비교에서는 제외했습니다.

## 발견해서 수정한 문제

| 문제 | 수정 | 확인 방법 |
| --- | --- | --- |
| 스테이지 전환 중 정지했다 재개하면 BGM이 계속 멈출 수 있음 | 전환 단계에서도 오디오 재생·준비 완료 경로를 허용 | 실제 카운트다운 후 오디오 재생 상태 검사 |
| 계속하기 버튼이 숨겨지면서 키보드 포커스가 사라짐 | 숨기기 전 포커스를 기억하고 재개 후 조작 버튼으로 복귀 | 재개 후 활성 요소 검사 |
| 320px 화면에서 헤더 버튼 정렬·조작 영역이 불균형 | 두 버튼 정렬 수정, 44px 조작 영역 확보 | 화면 크기별 영역 검사와 이미지 확인 |
| FLOW 표시와 순간 알림의 겹침 | 콤보 영역의 높이와 아래 여백 확보 | 모바일 화면 이미지 확인 |
| 영어 설정에서 BGM 음량 표시와 슬라이더 겹침 | 음량 행을 세로 배치하고 너비 제약 보완 | 320px 영어 설정의 실제 위치 검사 |
| 일치하는 블록이 없어도 공급이 해결해 줄 것처럼 안내 | ‘현재 NEXT와 맞는 맨 아래 블록이 없어요’, ‘일치하는 블록 없음’으로 변경 | 실제 16스테이지 실패 관찰 후, 막힌 보드 회귀 검사 추가 |

마지막 안내 수정은 실제 상태를 정확히 알리는 수정입니다. 막힌 숫자 배열을 자동으로 풀거나 난도를 낮추지는 않았습니다. 기존 점수 공식·버스트 수치·Classic 규칙을 이번 테스트 과정에서 변경하지 않았습니다.

## 검증 결과와 범위

- 빌드 및 산출물 검증 통과. production 10개 파일과 Lab 10개 파일 구성을 확인했습니다.
- 기존 몰입도 검사: 충전·보너스·실패·시간 초과·정지·스테이지 전환·클러치·기록·재시작·화면 크기·영어·동작 줄이기·공급 대기·실제 production 입력을 확인했습니다.
- 새 통합 검사 **15개 통과**: NEXT 후보, 조기 공급의 안전·예산, 버스트 해소, 막힘 중 시간 처리와 정확한 안내, 번개 수명, 알림 우선순위, 정지와 대기 입력, BGM, 키보드, 효과음·설정, 초보 안내, 저장·다른 탭의 기록, 화면·영어 설정, 저장소 차단을 확인했습니다.
- Lab 검사 **8개 통과**: 10→11 전환, 안전 신호 수명, 세 가지 퍼펙트 경로, 웨이브 간격·재정렬·진입, 위험선 초기화를 확인했습니다.
- JavaScript 문법·변경 공백 검사 통과.

통합 검사는 요청 가로채기로 테스트 브라우저에만 상태 설정 장치를 넣어 경계 조건을 재현합니다. production 파일에 이 장치를 저장하지 않습니다. Lab 검사는 기존 Lab 메시지 경로를 사용합니다. 아래 직접 플레이는 이와 별개로, 수정하지 않은 production 빌드에서 진행했습니다.

화면 크기는 320×568, 390×844, 430×932, 1280×900을 확인했습니다. 데스크톱 Chrome 검증이며 실제 iPhone·Android의 터치, 소리의 주관적 품질, 진동 체감, 장시간 발열·프레임 성능은 아직 검증하지 않았습니다.

## 직접 플레이 방법과 기록

현재 NEXT, 작은 NEXT, 각 라인의 보이는 숫자와 위치를 읽고 UI 버튼을 클릭했습니다. 정답 후보 중 다음 숫자가 남는 선택을 우선하고, 비슷하면 위험선에 가까운 라인을 골랐습니다. 충전되면 대체로 즉시 버스트를 사용했습니다. 상태 주입, 스테이지 건너뛰기, 점수 편집, 속도 변경은 사용하지 않았습니다. 기록을 정리할 때는 수동 정지를 사용했습니다.

첫 판은 정답만 골라 440콤보까지 갔지만, 16스테이지 36/43에서 현재 1과 일치하는 맨 아래 블록이 없는 상태에 빠졌습니다. 버스트는 1/4·남은 5.3초로 보호됐지만 보드는 계속 내려왔고 종료됐습니다. 이는 게임 전체가 멈춘 현상은 아닙니다. **버스트 시간 보호와 생존 보장은 다르다**는 점이 드러났습니다.

재도전 초반에는 제 조작 루프가 처리 중에도 추가 입력을 보내 오답이 늘었습니다. 이를 게임 결함으로 단정하지 않았습니다. 이후 선택 불가 상태가 지속되는지와 애니메이션 종료를 확인한 뒤 입력했습니다. 5스테이지 이후에도 막힘 대응을 위한 입력이 몇 차례 있었고, 콤보 손실 뒤 게임을 이어 갔습니다.

두 판은 고정 화면·같은 난도의 통제 비교가 아닙니다. 실제 목표 수가 첫 판 16스테이지 43개, 재도전 16스테이지 23개로 달랐으며 재도전 18스테이지부터 43개였습니다. 최종 화면은 547×1072였습니다. 소스상 블록 높이와 보드 높이에서 계산한 웨이브 간격이 공급 예산과 목표 수에 영향을 줍니다. 각 시점의 화면 크기를 전부 기록하지 않았으므로 목표 차이의 원인을 화면 크기로만 확정하지 않습니다.

```sh
npm run build
npm run verify:build
node scripts/test-immersion.cjs
node scripts/test-flow.cjs
node scripts/test-lab.cjs
```

현재 환경에서는 위 세 검사 실행에 공용 런타임의 `node_modules`를 `NODE_PATH`로 지정했습니다. 자동 검사 서버는 각 검사 종료 때 닫힙니다. 직접 플레이용 로컬 서버만 남았으며 외부 서비스 배포는 없습니다.
