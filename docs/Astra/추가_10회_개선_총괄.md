## 이번 요청의 완료 범위

첫 임무와 동일하게 기능 제안 PDF를 기준으로 몰입도를 개선하는 작업을 **추가 10회** 수행했습니다. 각 회차에 문제 선정, 구현, 코드 정적 검토, 기록을 남겼습니다.

**현재 상태는 소스 구현 완료·실행 검증 전입니다.** 창작자님 요청에 따라 실제 플레이, 브라우저 확인, 자동화 테스트, 실제 기기 테스트, 빌드와 배포를 실행하지 않았습니다. 현재 열려 있는 로컬 게임과 `dist/prod`, `dist/lab`은 이전 산출물이며 이번 변경을 반영하지 않습니다.

이 문서는 추가 10회 구현 당시 작업 범위의 안내입니다. 이전 [몰입도 개선 보고서](몰입도_개선_구현과_향후과제.md)에 적힌 테스트 통과는 이전 구현에 대한 결과이며, 이번 10회 변경에 그대로 적용되지 않습니다.

## 현재 규칙과 설정

- 버스트는 정답 16개로 충전하며, 직접 발동 후 선택 가능한 6초 안에 4연속 성공하면 100점을 추가합니다.
- 버스트 낙하 속도는 40%, 성공 후 1.2초의 해소 구간은 65%입니다. 스테이지·웨이브 시간에도 같은 배율을 적용합니다.
- NEXT 공급이 없어 고를 수 없는 시간에는 기존 버스트 시간 보호를 유지합니다. 새 후보 선택과 안전한 조기 공급이 모든 대기를 없애지는 않습니다.
- 번개·클러치·FLOW 표시에는 별도 점수를 추가하지 않습니다.
- 효과음은 기본 켜짐, 진동은 기본 꺼짐, 콤보 화음은 기본 켜짐입니다. 콤보 화음은 효과음이 켜져 있어야 들립니다. BGM 버튼은 여전히 BGM만 제어합니다.
- 키보드 `1 / 2 / 3 / 4` 또는 `A / S / D / F`는 왼쪽부터 라인을 선택합니다. `B`는 버스트, `P` 또는 `Esc`는 일시정지·재개입니다. 숫자 키는 블록의 값이 아니라 라인 번호입니다.
- 최고점 저장은 최대 초당 한 번과 수명주기 전환 시에 시도합니다. 브라우저 저장소 차단이나 강제 종료까지 보장하지는 않습니다.

## 코드와 정적 검토 기록

변경한 제품 파일은 `app.js`, `index.html`, `styles.css`, `privacy.html`입니다. `README.md`에 최신 기록 진입점을 추가했습니다. 신규 오디오 파일이나 외부 서비스·분석 수집은 추가하지 않았습니다.

최종 통합 정리에서 다음을 확인·보완했습니다.

- JavaScript 문법 검사에서 오류가 나오지 않았습니다. 게임 코드를 실행한 결과가 아닌 파싱 결과입니다.
- HTML의 중복 ID와 코드에서 참조하는 누락 ID가 없었습니다.
- HTML의 고정 번역 키가 한국어·영어에 모두 존재했습니다.
- 새 효과는 시간·개수 제한과 정리 경로를 두었습니다. 고정 DOM 참조를 캐시하고 새 HUD 텍스트는 바뀔 때만 갱신합니다.
- 버스트와 같은 입력에 발생한 최고기록·클러치가 알림 큐에 들어가도록 연결했습니다.
- 스테이지 전환 후 공급에는 전환된 난도 값을 사용하도록 정리했습니다.
- 일시정지 중 대기 입력 제거, 숨겨진 재개 버튼의 포커스 이동, 새 판·메뉴의 상태 초기화를 검토했습니다.
- 회차별 Markdown 기록 10개를 확인했습니다. 공백 오류 검사에서 문제가 나오지 않았습니다.

**위 항목은 정적 검토이며 기능 동작, 화면 품질, 음향 품질, 성능을 입증하지 않습니다.** 이전에 작성한 `scripts/test-immersion.cjs`는 이번 수동 정지·기록 체크포인트·새 규칙에 맞춰 검토하고 확장할 후속 대상이며 이번에는 실행하지 않았습니다.

## 앞으로의 추천 방향

### 다음 단계는 기능 추가보다 통합 검증

버스트를 중심으로 손맛, 흐름, 위기, 성취, 재도전이 연결되는 구조는 마련했습니다. 다음 작업이 허용될 때는 먼저 새 기능 전체가 함께 동작하는지 검증하는 것이 우선입니다. 특히 아래 순서가 효율적입니다.

1. **규칙의 공정성:** 다중 정답 뒤 NEXT 선택, 조기 공급의 위험 여백, 버스트 시간과 스테이지 전환, 오답·게임오버 경계를 검증합니다.
2. **실제 모바일 조작:** 작은 화면의 새 헤더·버스트 버튼·설정 스크롤, 회전·확대·정지·재개·입력 대기열을 확인합니다.
3. **음향과 피로도:** iOS·Android에서 오디오 활성화와 BGM/효과음 분리, 합성 화음과 기존 BGM의 조화, 진동 세기를 평가합니다.
4. **학습과 재도전:** 짧은 안내만으로 버스트를 발견하는지, 준비된 버스트를 실제로 사용하는지, 기다림이 얼마나 남는지 관찰합니다.
5. **기록과 운영:** 저장 차단·손상·복수 탭·탭 이탈을 검증하고, 규칙 변경 전후 점수를 어떻게 구분할지 정합니다.

### 그 이후에 다룰 기능

제안서의 반복·교차·순환 숫자 패턴과 베이스·드럼·멜로디 분리 BGM은 아직 구현하지 않았습니다. 생성기와 음악 자산을 별도로 다뤄야 하므로 지금 넣은 콤보 화음을 완전한 적응형 음악으로 보아서는 안 됩니다.

온라인 순위표와 계정, 외부 분석 수집도 추가하지 않았습니다. 당장은 플레이 관찰과 소수의 로컬 기록으로 효과를 판단하고, 근거가 생긴 뒤 운영 기능을 결정하는 것을 권합니다. 커진 `app.js`는 후속 작업에서 규칙·피드백·저장·입력 모듈로 나누되 먼저 동작 회귀 기준을 마련해야 합니다.
